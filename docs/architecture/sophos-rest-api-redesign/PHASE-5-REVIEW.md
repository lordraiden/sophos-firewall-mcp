## Verdict

**CHANGES REQUIRED** — **1 High**, **3 Medium**, **6 Low**. No Critical finding.

The phase's headline deliverable — "one output convention, 0 off-convention tools" (`PHASE-5-PLAN.md:49`) — is
**not met**. Enumerating `tools/list` on the real server shows **3 of 152 tools still publish snake_case
output properties at every depth**: `audit_firewall_rules` (15 names), `explain_connectivity` (22) and
`find_object_usage` (9). The README, CHANGELOG and release notes state the opposite as a universal fact
("Every published output property is the Sophos wire name"), and no global test asserts the invariant, so
the gap passed CI. The audit models' own docstring records the snake_case choice as deliberate
(`models/audit.py:24`), but neither the plan nor the release documentation carves out the exception.

The rest of the phase is in good shape. M9, M10, M12, M13, M14, M15, M16, L1, L3, L7, L8, L9, L10 and P5-D1
each match the recorded finding, each has a test, and each behaves as claimed when I exercised it. The
`position` derivation is correct for a page offset and counts WAF rules; NAT `kind` never guesses; the four
unpaginated lists return `pages: null`; all 41 paginated tools default to `page_size: 10`; the DNS host
entry reads the nested shape. The wire request body is unchanged (the input schema structure is byte-identical
to `origin/main` once descriptions/defaults are stripped). The live SKIP run respected the safety rules with
one disclosed deviation. The SFOS 23 positioning is accurate and does not overclaim, and the GitHub
description/topics are set. All gates are green when I run them.

The three Medium findings are the **incomplete L6 fix** (the VPN output models still publish the epoch
sentinel), the **M11 documentation overclaim** (only 5 of 41 paginated descriptions state a page size), and
the **missing global output-naming test** that let the High finding through. All are cheap, concrete fixes.

## Residual risks

- **The audit output naming is a live inconsistency for 0.6.0.** A client that trusts the README's "every published output property is the Sophos wire name" and writes one camelCase parser will read `ruleName`/`objectName`/`checksRun` as `None` on the three audit tools — the exact "confident wrong answer" class the phase-4 feedback warns about. A schema-driven client is unaffected. Fixing it is a breaking change, but 0.6.0 is already breaking and the alternative is a documented exception.
- **The L6 gap is a cross-domain inconsistency.** `createdAt` is `null` on an interface and `1970-01-01T00:00:00Z` on an IPsec profile. An agent that filters "never created" objects will miss the VPN ones.
- **The `position` derivation is a client-side inference, not a contract value.** It is exact for an unfiltered page and for the requested page size, but it is wrong if the appliance ever returns a page whose size differs from the requested `page_size`, and it is the position within a filtered sequence when `name_contains`/`name_not_equals` is set (documented). The live run did not exercise it.
- **The `kind` derivation cannot see a combined SNAT+DNAT rule.** The contract has no combined variant, so `unknown` is the honest answer, but a caller that treats `unknown` as "no translation" will misread a rule that has both.
- **The live SKIP coverage is 6 of 24.** 17 remain deferred (connectivity risk or no create tool) and 1 is appliance-blocked; the read-only surface is 77 PASS / 18 SKIP, not a complete live matrix.
- **The release pack is prepared but not published.** The tag, image and GitHub release are still pending owner approval; the publication checklist has one stale item (finding 7) and the "APPROVE" item is now blocked by this review.
- **The private-SDK seam** (`MCPServer._tool_manager`, `Tool.fn_metadata.arg_model`, `Tool.parameters`) is still a pinned-version dependency; the tests pin it, but an SDK upgrade breaks argument validation for every tool.
